# Провайдер ChatGPT в браузере

Реализован 11 ноября 2026 года. Выбирается в приложении: **Настройки ИИ → ChatGPT в браузере**.

## Настройки

- Модель: GPT-6, отдельный временный чат для каждого запроса.
- Сила рассуждения: **Instant / Medium / High**. По умолчанию Instant. Положение шкалы и название режима проверяются перед отправкой; неизвестная шкала или недоступная модель останавливают отправку.
- Повторы невалидного ответа: **0, 1 или 2** на один вызов LLM. По умолчанию один повтор.
- Адрес локального моста: `http://127.0.0.1:8791`. Разрешены только HTTP loopback-адреса; переадресации HTTP не выполняются.
- Токен моста можно указать в настройках. При отсутствии сохранённого токена backend читает `CHATGPT_BRIDGE_TOKEN_FILE`, по умолчанию `../data/secrets/chatgpt-bridge-token` при запуске из `backend/`. Значение не возвращается в браузер и не сохраняется в PostgreSQL. Файл должен быть доступен только владельцу.

Нужен userscript **0.3.0**: [локальная установка](http://127.0.0.1:8791/worker.user.js). Совместимый старый worker может выполнять прежние диагностические запросы Instant, но запросы настоящего провайдера проекта выдаются только 0.3.0. Если такого окна нет, мост сразу возвращает ошибку готовности вместо многоминутного ожидания в очереди.

Параметры и выбранный провайдер сохраняются в новой неизменяемой AI revision. Уже поставленные в очередь ходы используют свои исходные revisions. Память, изображения и остальные настройки сохраняются штатным способом. Доступность режима зависит от аккаунта ChatGPT; сведения об уровнях дополнительно сверены с [официальной документацией моделей](https://learn.chatgpt.com/docs/models).

## Проверка ответа и повторы

Мост проверяет наличие единственного JSON-объекта; пустой ответ, лишняя `}` или другой неверный JSON отклоняются. Адаптер провайдера затем проверяет форму ответа для роли по тем же схемам, которые используются для структурного вывода: обязательные поля, типы, неизвестные поля, допустимый переход сцены, четыре варианта с разными ID, целые неотрицательные количества и диапазон прогресса 0–100. Обязательные строки должны быть непустыми. Для гибких setup/editor ролей специфические проверки остаются на уровне приложения.

При подтверждённом невалидном ответе выполняется новый вызов в новом временном чате, в пределах выбранного лимита. Невалидное содержимое не подставляется в историю и не «исправляется» удалением символов. В метриках ответа фиксируется число повторов `ProtocolRetries`.

Транспортная ошибка, отмена, таймаут или неопределённость после разрешения отправки не запускают повтор того же LLM-запроса. Недоступность модели до отправки тоже требует проверки рабочего окна. Для браузерного провайдера очередь не перезапускает целиком неудачный ход: `max_attempts=1`; бюджет повторов принадлежит отдельному вызову LLM. Это предотвращает умножение повторов и повторное проигрывание всего хода.

Проверка формы ответа не заменяет существующие проверки свидетельств, ресурсов, квестов и канона. Они выполняются обычным Pipeline. Текст writer не стримится до окончания его проверки; штатный ранний показ готового продолжения остаётся на уровне Pipeline. Опция стриминга для этого провайдера отключена, поскольку мост возвращает проверенный буферизованный ответ.

Запросы приложения используют общий ограничитель одного HTTP-вызова к мосту. Каждый worker также получает не более одного активного задания. Для Instant установлен бюджет вызова 3 минуты, Medium 5 минут, High 10 минут; общий лимит выполнения хода по-прежнему ограничивает весь Pipeline. Контекст настоящего запроса ограничен 128 KiB, тело HTTP и результат — 512 KiB. Прежние диагностические запросы сохраняют собственный меньший лимит.

## Запуск

1. Запустить `./start.sh` и открыть приложение. Если сохранён именно браузерный провайдер со стандартным адресом, скрипт поднимет отсутствующий локальный мост автоматически. Уже работающий мост используется повторно.
2. Оставить открытым одно настроенное окно Chromium с worker 0.3.0 и нажать «Запустить».
3. В «Настройки ИИ» выбрать ChatGPT, режим рассуждения и число повторов, затем нажать **«Сохранить и включить ChatGPT в браузере»**.

Если мост нужен отдельно до выбора провайдера, запускается `./start-chatgpt-bridge.sh`. Токен сохраняется между перезапусками. Доступ к аккаунту и CAPTCHA остаются в видимом рабочем окне.

Установка кода сама не активирует новый провайдер. На финальной проверке приложения уже выбрана revision 30: `chatgpt_browser`, Instant, один повтор. Этот выбор прочитан из реального API настроек. Рабочие процессы не перезапускались во время пользовательской генерации. Финальные изменения лимитов контекста, классификации ошибок до отправки и запрета HTTP redirect проверены тестами; для их загрузки в уже работающие процессы нужен штатный перезапуск приложения и моста после окончания генерации.

## Проверки

- Полный `go test ./...`, `go vet ./...`; race-проверки изменённых пакетов.
- Полный frontend typecheck, lint, тесты и сборка; 59 тестов интерфейса, включая сохранение High/двух повторов, восстановление Medium/нулевого бюджета и сохранение остальных настроек.
- 51 DOM-проверка worker: все три режима, переход с High на Medium, запрет отправки при неизвестной шкале или неподтверждённом режиме, точная корреляция, большие сообщения и пустой ответ.
- Полный Pipeline с настоящим браузерным адаптером и тестовым HTTP-мостом: первый writer-ответ отклоняется, второй принимается, в Canon попадает один ход; при исчерпании попыток Canon остаётся пустым. Проверены запрет повторной отправки при неопределённом результате и отмене, отсутствие утечки невалидного текста в callback, дубли ID вариантов, неподдерживаемые поля, лимит прогресса и запрет HTTP redirect.
- Живой вызов адаптера проекта через одно пользовательское окно 0.3.0: Instant **7,30 с**, Medium **12,70 с**, High **13,30 с**. Во всех трёх случаях получен корректный JSON `goal`, дополнительных попыток не понадобилось. Это функциональные пробы, не статистическое сравнение скорости или качества. [Сохранённые результаты](benchmarks/chatgpt-provider-integration-live-2026-11-11.json).
- Живой экран `/settings/ai` проверен после запуска backend/frontend. Сохранение параметров проверено интеграционными тестами UI и сервиса настроек. Настоящие пользовательские истории тестами не изменялись.

Повторы в этом провайдере — новая рабочая политика, явно запрошенная после экспериментов. Ранее проведённые сравнительные серии остаются без подмены отказов и без ретраев ради улучшения их результатов.
