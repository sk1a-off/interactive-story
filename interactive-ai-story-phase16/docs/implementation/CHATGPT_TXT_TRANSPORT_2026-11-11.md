# Передача каждого запроса через TXT

## Причина изменения

Последний неудачный ход завершился на `quest_evaluator` с HTTP 413. План и Writer успели завершиться; запросы мира и героя также прошли. Лимит 128 KiB был локальным ограничением моста, а не ответом модели о её контекстном окне. На той же итерации соседние запросы занимали около 122 KiB. В Canon неудачный ход не сохранялся.

По запросу пользователя весь запрос теперь прикрепляется как UTF-8 TXT для **каждого** вызова браузерного провайдера. Автоматического возврата к вставке полного текста нет.

## Формат и подтверждение

Один файл `story-<уникальный ID>.txt` содержит ID, исходные SYSTEM INSTRUCTIONS, USER INPUT и RESPONSE FORMAT. JSON форматируется без преобразования чисел через float64: большие целые, Unicode, значения строк и переносы сохраняются. Данные не обрезаются и не суммируются. В поле чата остаётся короткая инструкция со ссылкой на это имя и ID.

Worker 0.4.0 строит File из UTF-8 байтов и проверяет размер и SHA-256. Через стандартное поле загрузки файл прикрепляется к новому временному чату. Worker ждёт появления нужного имени вне редактора, исчезновения признаков загрузки, отсутствия ошибки и доступности кнопки отправки. После стабильного состояния он подтверждает имя, размер и хеш серверу через `/attachment`. Сервер запрещает `/send`, пока подтверждение не совпало с текущим lease. Непосредственно перед кликом worker ещё раз проверяет вложение. После отправки проверяются и короткое сообщение, и отдельная карточка файла текущего задания.

Подтверждение означает проверку подготовленных байтов и наблюдаемого состояния UI; оно не является независимым хешем, полученным от серверов ChatGPT. Живые тесты чтения случайных маркеров отдельно проверяют, что модель действительно получила файл.

Смена режима рассуждения, очередь нескольких браузеров, проверка JSON/ролевого контракта и ограниченные повторы невалидных ответов сохранены. Ошибка загрузки останавливает запрос до разрешения отправки. Неопределённый результат после отправки не переотправляется.

Новые файловые задания выдаются только worker 0.4.0. Старый 0.3.0 может обслуживать прежние текстовые диагностические задания, но не получит файл. Наличие только старых окон возвращает явную ошибку с требуемой версией.

## Ограничения и запуск

По умолчанию `CHATGPT_BRIDGE_INPUT_FORMAT=txt`. Явный операторский режим `text` оставлен для диагностики; он не включается автоматически. `start.sh` поддерживает обе новые переменные.

`CHATGPT_BRIDGE_MAX_PROMPT_KIB=1024` задаёт локальный предел суммы файла и короткой инструкции; допустим диапазон 128..4096. Входной HTTP-предел отдельно учитывает разрастание JSON при экранировании. В `/status` видны активный формат и лимит байтов. При превышении возвращается HTTP 413 с фактическим размером, пределом и областью ограничения; backend показывает числовые значения вместо предположения об устаревшей версии.

Файл не увеличивает контекстное окно модели. У загрузок есть отдельная квота: [официальная справка OpenAI](https://help.openai.com/en/articles/8555545-uploading-files-and-audio-to-chatgpt) указывает до 80 файлов за 3 часа с возможным снижением. Пользователь выбрал TXT для каждого запроса после сообщения об этом ограничении. Ошибка загрузки не обходится вставкой текста.

Нужен userscript **0.4.0**: `http://127.0.0.1:8791/worker.user.js`. Во время простоя обновлены приложение и мост, токен и активная AI revision 30 сохранены. Оба реальных рабочих окна обновлены пользователем до 0.4.0 и запущены.

## Проверки

- Полный `go test ./...`, `go vet ./...`, race-проверки моста, адаптера и Pipeline проходят.
- 59 DOM-тестов worker проходят. Новые отрицательные случаи: неверный хеш, отсутствие файлового input, незавершённая/ошибочная загрузка, отказ подтверждения, удаление вложения после разрешения отправки, отсутствие карточки файла в отправленном сообщении.
- Серверный тест проходит всю последовательность claim → запрет преждевременного send → отказ неверному SHA-256 → подтверждение → send → result. Проверены совместимость worker, сохранение большого целого и ограничение размера.
- Frontend: build, lint, проверка настроек провайдера проходят.

Живые проверки выполнены через настоящий адаптер и два Chromium с worker 0.4.0, без действий в пользовательских историях:

| Проверка | Результат |
| --- | --- |
| Короткий запрос с TXT | корректный JSON, 10,70 с, 0 повторов |
| Большой TXT | файл **225 937 байт**, 58,41 с; случайные значения из начала и конца точно прочитаны |
| Шесть запросов с отдельными TXT | 6/6 корректных ответов за 39,50 с; каждый браузер обработал три задания; пик два одновременно выполняемых запроса; 0 повторов |

Большой тест выполнялся одновременно с очередью шести коротких запросов. Эти времена включают ожидание и не используются для сравнения скорости с прежним форматом. Все восемь заданий имеют серверное подтверждение вложения и терминальное состояние complete. Сохранены только синтетические ответы и метаданные; тексты реальных историй в отчёты не включались.
