# Параллельная очередь браузеров ChatGPT

## Граф выполнения

Для браузерного провайдера включён тот же граф зависимостей, что и для hosted-провайдера. Формирование плана остаётся перед Writer. После проверки Writer запускаются три независимых запроса: world_evaluator, state_evaluator и quest_evaluator. Choices ждут нормализованных изменений героя и квестов, но могут выполняться одновременно с ещё работающим world_evaluator. Canon сохраняется одной транзакцией только после завершения всех ветвей и общей проверки. При ошибке ветви остальные вызовы присоединяются до возврата; частичного сохранения нет.

Подготовка истории использует существующий граф зависимостей компонентов: готовые независимые компоненты уходят в очередь сразу, зависимые получают только завершённый контекст. Многокомпонентный ИИ-помощник также использует уже существующий параллельный путь.

Для одного временного ряда (timeline) одновременно выполняется один ход. Разные истории/ветви с браузерным провайдером могут выполняться одновременно. Браузерные запросы не блокируют локальный GPU-провайдер; сам локальный llama.cpp остаётся последовательным. Идемпотентность, контроль head и max_attempts=1 браузерного хода сохранены.

## Очередь и рабочие окна

Приложение допускает несколько HTTP-запросов к мосту одновременно. По умолчанию верхний предел — 32 (`CHATGPT_BROWSER_PARALLELISM`, 1..4096). Мост складывает их в очередь, каждый свободный worker 0.3.0 забирает одно задание под уникальной арендой. Один worker не может получить второе, пока первое активно. Верхний предел занятых окон — 32 (`CHATGPT_BRIDGE_MAX_ACTIVE`, 1..4096). Лишние окна просто опрашивают очередь; автоматического открытия Chromium нет.

С одним рабочим окном всё работает последовательно; с несколькими доступные независимые роли распределяются между ними. Число окон не меняет граф зависимостей. Остановленное окно или CAPTCHA требуют вмешательства пользователя; неопределённый результат после отправки по-прежнему не переотправляется.

Запросы хода имеют приоритет перед ещё не выданными запросами иллюстраций. Уже начатая генерация изображения не прерывается. Внутри класса приоритета сохраняется FIFO. Очередь проекта вмещает минимум 128 незавершённых запросов, либо удвоенный лимит моста для большей конфигурации; переполнение явно возвращает 429.

Ожидание выдачи задания ограничено отдельно: до 10 минут. После выдачи worker получает полный бюджет режима: Instant 3 минуты, Medium 5, High 10. Общий HTTP-бюджет включает ожидание и выполнение; исходный контекст операции и лимит всего хода по-прежнему имеют приоритет. Отмена ожидающего запроса удаляет его из активной выдачи. После разрешения отправки нет автоматического повторного назначения задания другому браузеру.

## Запуск

Обновление userscript не требуется: версия 0.3.0 уже понимает эти задания. Открыть нужное количество отдельных рабочих вкладок/окон Chromium:

`https://chatgpt.com/?temporary-chat=true#story-bridge-worker`

После открытия или изменения адреса выполнить Ctrl+R и нажать «Запустить» в каждой панели. В новых независимых вкладках worker получает UUID из sessionStorage. Настройки провайдера/режима/повторов остаются общими в «Настройки ИИ», каждый запрос создаёт новый временный чат.

Новые параметры `.env.example` поддержаны `start.sh`. Backend и мост нужно перезапустить для загрузки нового планирования; токен и AI revision не меняются.

## Проверки

- Реальный браузерный адаптер с HTTP-транспортом: восемь запросов обслуживаются одним и четырьмя имитируемыми worker; проверены пересечение четырёх аренд, ограничитель, отсутствие потерянных/повторных заданий и завершение очереди.
- Реальный Pipeline и HTTP-адаптер: все три evaluator одновременно доходят до барьера; Choices ждут героя/квестов и не ждут независимую ветвь мира. Сохранение ждёт мир.
- Ошибка evaluator не запускает Choices и не оставляет работающих ветвей или частичного Canon.
- Проверены приоритет хода над иллюстрацией, полное время выполнения после восьми минут в очереди, один lease на worker и диапазон конфигурации.
- PostgreSQL: откатываемая транзакция с временными таблицами очереди проверяет параллельные browser-ходы разных timelines, последовательность одной линии и независимость локального GPU. Пользовательские очереди из теста недоступны.

Это функциональная проверка параллелизма, а не статистическое доказательство ускорения. Итоговая задержка зависит от числа свободных окон и скорости ответов аккаунта.

При загрузке новой версии выполнен штатный перезапуск приложения и моста с сохранением токена и AI revision. Первый живой запуск шести запросов после перезапуска был отклонён до отправки: рабочие окна ещё не возобновили heartbeat. Ни одного запроса модели в этой попытке не было. [Отдельный отчёт готовности](benchmarks/chatgpt-parallel-live-no-workers-2026-11-11.json) сохранён, а последующая проверка не подменяет этот результат.

Итоговый автоматический прогон: полный `go test ./...`, `go vet ./...`, race-проверки моста, Pipeline, setup, политики, конфигурации и HTTP-адаптера проходят; 51 DOM-проверка неизменённого worker проходит. PostgreSQL-проверка выполнена на настоящей базе внутри откатываемой транзакции. Новый backend запущен с `browser_provider_parallelism=32`, мост — с `max_active=32`; активная AI revision 30 сохранена. При быстром перезапуске также исправлена ложная занятость порта из-за TIME_WAIT в предварительной проверке `start.sh`.

Живая проверка завершена после возобновления двух пользовательских окон 0.3.0: шесть синтетических запросов через настоящий адаптер проекта выполнены за **27,70 с**. Каждый браузер обработал ровно три задания, метки sent/finished подтверждают пик **два одновременно выполняемых запроса**. Все шесть ответов — корректные JSON-объекты с маркером именно своего входа; `ProtocolRetries=0` у каждого. Пользовательские истории тестом не изменялись. [Ответы и задержки](benchmarks/chatgpt-parallel-live-2026-11-11.json), [назначения worker и интервалы](benchmarks/chatgpt-parallel-live-metadata-2026-11-11.json). Это проверка реальной очереди и корреляции, без сравнения скорости с последовательным запуском. Код проверки сохранён в `browser_parallel_live_test.go` и включается только явной переменной `CHATGPT_BROWSER_LIVE_PARALLEL=1`.

Сведения о worker 0.3.0 выше относятся к исходной текстовой проверке очереди. После перехода каждого запроса на TXT нужны рабочие окна 0.4.0; параллелизм повторно подтверждён живым прогоном с файлами. [Изменение транспорта](CHATGPT_TXT_TRANSPORT_2026-11-11.md).
